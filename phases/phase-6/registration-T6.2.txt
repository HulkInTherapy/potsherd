1. tests/llm.test.ts — ONE LINE, and it matters
-----------------------------------------------

The guard at `no command outside MODEL_CALL_VERBS reaches Llm.open` follows a
command's imports through every workspace package, using this map:

    const WORKSPACE: Record<string, string> = {
      '@potsherd/core': 'packages/core/src',
      '@potsherd/mcp': 'packages/mcp/src',
    };

ADD:
      '@potsherd/bridges': 'packages/bridges/src',

`commands/export.ts` imports from '@potsherd/bridges'. Until that line is
there, the guard walks past the import and `export` is unchecked — the exact
hole phase 5 found for '@potsherd/mcp' and closed by widening this map. T6.2
deliberately did not edit this file (it is shared); the line is one addition
inside an object literal and cannot conflict semantically.

Nothing in packages/bridges calls a model, and none should ever: the whole
package is read-only federation and file copying.

---------------------------------------------------

3a. beside the other command imports (after `import { runSetup, … }`):

3b. the block itself. Place it after the `doctor` block, before the
    `if (argv.length <= 2)` tour:

  const exportCmd = addGlobals(
    program
      .command('export')
      .description('write your cards out — to markdown, or into another memory tool')
      .requiredOption('--to <target>', `where to write: ${EXPORT_TARGETS.join(', ')}`)
      .argument('[dir]', 'the directory to write into (markdown)')
      .option('--transcripts', 'also write the full conversations, one file each')
      .addOption(new Option('--limit <n>', 'cap on transcripts written').argParser(Number))
      .option('--yes', 'required to write into another tool’s store'),
  ).addHelpText('after', `
example:
  potsherd export --to markdown ./vault
  potsherd export --to markdown ./vault --transcripts   # cards + full conversations
  potsherd export --to markdown ./vault --json | jq .cards.files
  potsherd export --to agentmemory                      # dry run: says what it would push
  potsherd export --to agentmemory --yes                # actually writes into their store`);
  exportCmd.action(async (dir: string | undefined, opts: Record<string, unknown>) => {
    const o = globals(program, exportCmd, opts);
    await run(
      () =>
        runExport({
          ...o,
          to: String(opts['to']),
          ...(dir ? { dir } : {}),
          transcripts: Boolean(opts['transcripts']),
          ...(opts['limit'] ? { limit: Number(opts['limit']) } : {}),
        }),
      o,
    );
  });

  Note: `--yes` is read by `globals()`, which already picks up `local['yes']`.
  It is declared on the command so that `--help` shows it and commander does
  not reject it; no extra plumbing is needed.

  Note: the local is named `exportCmd`, not `export`, because `export` is a
  reserved word.

4f. commands/find.ts — the human view. One line under the results:

        if (federated) print(`  ${t.dim(federationLine(federated.bridges))}`);

    which renders, on a machine with none of them installed:

      claude-mem: not installed  ·  agentmemory: not installed  ·  notes: 4 hits

    Every one of the four presences has its own wording. `federate()` never
    mutates the local result: `federated.hits` and `federated.sessions` are
    exactly what `recall()` returned, and the foreign hits live only in
    `federated.external`, so a caller that ignores both fields sees precisely
    what `find` has always produced. `federated.order` interleaves the two by
    score for a renderer that wants one page.

    A bridge that is absent contributes a line and no hits. It cannot change
    the local ranking, cannot throw, and cannot slow `find` past its ceiling
    (claude-mem's localhost probe is 1.5 s, agentmemory's whole call is 5 s).

6. doctor --privacy — the lines the export path needs
-------------------------------------------------------

6a. READS. `--privacy` lists every path potsherd reads. The bridges add four
    kinds, and all four are read-only — no bridge ever opens another tool's
    file for writing. Append to `reads` in runDoctor:

  import { claudeMemDbPath, agentMemoryDirs, notesPaths } from '@potsherd/bridges';

  const bridgeReads = [
    claudeMemDbPath(),
    ...agentMemoryDirs().map((c) => c.path),
    ...notesPaths(o.claudeDir ? { claudeDir: o.claudeDir } : {}).map((c) => c.path),
  ];
  const reads = dedupe([...report.pathsRead, ...harnessReads, ...bridgeReads]);

    `notesPaths()` is exported precisely so this list cannot drift from what
    the code opens — it is the same function the bridge itself walks.

    The existing `(absent)` suffix already handles the common case: on a
    machine without claude-mem the receipt shows the path and marks it absent,
    which is the honest answer and better than omitting it.

6b. WRITES. `export --to markdown` writes into a directory the user names. It
    is not another tool's store and needs no consent gate, but `03` §11 says
    this receipt lists every path written, and it has under-reported once
    before. Add to `written`:

    // `export --to markdown <dir>` writes the cards mirror, and with
    // --transcripts the full conversations, into a directory the user names
    // on the command line. Files are 0600, like everything else potsherd
    // writes. Nothing is written anywhere else by this verb.
    '<the dir you give to  export --to markdown>',

6c. WRITES ONLY AFTER CONSENT. `export --to agentmemory --yes` is the only
