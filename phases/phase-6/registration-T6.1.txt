4. WHAT EACH `doctor` LINE SAYS, AND WHY IT HAS TO
--------------------------------------------------

The phase file requires the line to say plainly whether a harness is **not
installed**, **installed with no sessions**, or **parsed**. "0 sessions" alone
cannot distinguish the first two, and they call for completely different things
from the user, so each adapter branches explicitly:

gemini
    absent   Gemini CLI not installed
    empty    Gemini CLI installed, no saved chats (use /chat save) · unverified format
    empty    Gemini CLI installed, no tmp/ yet — no chats saved · unverified format
    ready    <n> checkpoints · unverified format

opencode  (four states: a database can be present and unreadable)
    absent       opencode not installed
    empty        opencode installed, no sessions yet · unverified format
    empty        opencode installed, no sqlite store — this install uses
                 storage/ json, which potsherd does not read yet
    unsupported  <the reason describeStore() gave> · unverified format
    ready        <n> sessions [· <k> stores unsupported] · unverified format

copilot
    absent   Copilot CLI not installed
    empty    Copilot CLI installed, but it has written no session-state/ · unverified format
    empty    Copilot CLI installed, session-state/ holds no sessions · unverified format
    ready    <n> sessions [· <k> unreadable] · unverified format

Every one of those branches has a test.
