NO NETWORK — established, not asserted
--------------------------------------
The whole walk runs inside a macOS sandbox profile that denies `network*`.
Proof the profile denies, taken on the same machine at the same time:

  curl https://huggingface.co                       outside sandbox → 200
  sandbox-exec ... curl -m 8 https://huggingface.co inside          → exit 6 (DNS)
  sandbox-exec ... curl -m 8 http://1.1.1.1         inside          → exit 7 (TCP)

Both name resolution and a raw TCP connect to a literal IP fail inside. And
the walk itself is the second proof: run against the same corpus before this
change, `index` inside the sandbox printed
  "first run: fetching the 32.4 MB embedding model into …"
and then reported "no vector index: embeddings unavailable" — i.e. the old
default really did reach for the network and really was denied. After the
change that line is gone and nothing is reported unavailable, because nothing
was wanted.

The same establishment is in the suite: tests/index.test.ts, "runs where the
network is denied, and --embed cannot" runs two commands under one sandbox —
`index --embed` fails at the fetch (which is what proves the sandbox denies)
and `index` exits 0 and indexes (which is the claim). Skipped off darwin;
the portable tests beside it check that the models directory is never created.

7. DECISIONS TAKEN, SO THEY ARE ON THE RECORD
================================================================================
--embed / --no-embed / no flag are three states, not two:
  no flag   text only. no model, no download, no network. receipt's last line
            offers the upgrade.
  --embed   the opt-in. the only path that touches the network.
  --no-embed  text only AND stop offering — the upgrade line is not printed.
            Kept rather than deleted because it is the documented spelling of
            "offline, and I mean it" (hooks, CI, metered connections), and
            because `08` rule 8 will not have a flag that does nothing: this
            one's effect is visible by diffing two receipts, and a test does
            exactly that.
  --embed --no-embed  last flag wins, as getopt has always done. Tested.

the vectors row has three readings, not two:
  disabled, no vectors in the index    "—  text search only · no model, no network"
  disabled, no vectors, --no-embed     "—  skipped (--no-embed) · text search only"
  disabled, vectors already present    "1,294  not refreshed this run · potsherd index --embed"
  The third did not exist before. Someone who ran `--embed` last week and plain
  `index` today still has their vectors and this run did not refresh them;
  printing "— skipped" would be false and printing the bare count would be
  worse, because it would read as covering what was just parsed.

the upgrade line is suppressed when the index holds no exchanges at all.
Offering semantic search over nothing is noise.

--limit n:
  is a scope. `card --limit 5` needs no --all. `card` naming no scope at all
  is still an error.
  is the n newest across sessions AND ghosts. `planCards` sorts the merged
  list by COALESCE(ended_at,started_at) / COALESCE(last_ts,first_ts) desc, id
  asc, before the cut. It used to concatenate two ordered lists and slice, so
  on the reference archive `--limit 5` could not reach a ghost whatever its
  date — 93% of the archive was unreachable by the flag meant to make a small
  first run possible.
  caps AFTER the filters and after eligibility, never instead of them:
    --ghosts-only --limit 2   the two newest ghosts, nothing else
    --force --limit 2         the two newest, carded or not (force changes
                              what is eligible before the cut, not the cut)
    --dry-run --limit 2       the quote for exactly those two
    --limit 0 / -1 / "abc"    still refused by parseLimit, unchanged
  the id tie-break exists so two targets stamped the same second cannot swap
  places between the quote and the run it quotes.
