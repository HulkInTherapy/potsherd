3b. T4.0's one line, reconciled
================================================================================

`phases/phase-4/WAVE.md` records that the ask-eval harness had to write

    ask(db, g.question, { k: o.k, root, strict: false } as unknown as AskOptions)

because `AskOptions` was named in the pinned interface but never defined.
**The cast can simply be deleted.** `AskOptions` defines `k?: number`,
`root?: string` and `strict?: boolean` with exactly those names and types, so
the object literal is directly assignable:

    ask(db, g.question, { k: o.k, root, strict: false })

Two other things the harness relies on, confirmed against it:

  - `runCliStrict` spawns `ask <q> --strict --json --k <n> --potsherd-dir <root>`
    and reads the **exit status**. `ask` exits 2 on a refusal, 1 when nothing
    matched or nothing survived without `--strict`, 0 on an answer. Verified on
    the synthetic corpus: `s2-decoy-strict.txt`, exit 2.
  - `checkCitations` counts a quote that matches its exchange **only after case
    folding** as a fault — "a quote is a quotation". `filterAnswer` therefore
    emits **the transcript's own bytes**: folding is used to locate the passage
    (`matchSpan`) and the span is then sliced out of the source, so a model that
    re-cased, re-wrapped or curly-quoted its quote has that undone rather than
    forgiven. It also matches against `quotableText(unit.text)` — the two sides
    of the exchange with the `user:` / `assistant:` labels removed — which is
    exactly the string the harness's `dbCorpus` builds from `user_text` and
    `assistant_text`, so a quote can never carry a label that is in no exchange.
    `tests/ask.test.ts` holds all three.

4. T4.4 — the library interface, for `packages/core/README.md`
================================================================================

`ask()` is a library function first and a CLI verb second. The phase-5 Claude
Code plugin runs the readers with Claude Code's **native Agent tool** instead of
the Agent SDK, at zero marginal cost, by supplying one function.

```ts
import { ask, type AskReaderFn, type AskResult } from '@potsherd/core';
import { db as store } from '@potsherd/core';

// Called once per shortlisted session, in parallel, under `ask`'s own gate.
const readerFn: AskReaderFn = async (input) => {
  // input.question    the user's question
  // input.sessionId   the session this excerpt came from — the PER-HIT session,
  //                   so a subagent is read as itself and not as its parent
  // input.id8         the eight characters that name it on screen
  // input.project     last path segment, e.g. "Fulcrum"
  // input.harness     'claude' | 'codex' | 'cursor' | 'pi' | …
  // input.isSidechain a subagent transcript
  // input.isGhost     PROMPTS ONLY — the assistant side was swept and is not
  //                   recoverable. A reader must be told, and must not imply
  //                   what the assistant answered.
  // input.excerpts    "[seq 12 · 2026-08-21]\n<text>\n\n[seq 13 · …]\n<text>"
  //                   already capped at ~8 kB and redacted at rest
  // input.seqs        the seq numbers in `excerpts` — the only citable ones

  const reply = await runNativeAgent({
    system: READER_SYSTEM,           // exported; the phase plan's contract, verbatim
    prompt: input.excerpts,
  });
  return {
    found: true,
    quotes: [{ seq: 12, ts: null, text: 'copied character for character' }],
    answer_fragment: 'one or two sentences',
  };
};

const db = store.open({ root });
const result: AskResult = await ask(db, question, { readerFn, strict: true });
```

Guarantees that hold whatever `readerFn` does:

  - **Every quote it returns is re-checked by code** against the excerpt at the
    `(sessionId, seq)` it names, after whitespace/case/glyph normalisation. A
    reader cannot get an unverifiable quote onto the screen by being confident.
  - **`result.answer === result.sentences.map(s => s.text).join(' ')`**, always.
    There is no second copy of the model's prose in the module, so no path
    exists by which an unfiltered sentence reaches a caller.
  - **A rejected promise is not an error.** That session reports
    `found: false` with `readers[i].error` set and the run continues; one dead
    reader never fails the verb.
  - `readerFn` costs `ask` nothing: with it supplied, `result.spend.calls` is
    1 (the synthesizer) rather than k + 1.

Other `AskOptions` worth naming in the README:

  `filters`   the `03` §7 SearchFilters, exactly as `find` and `ls` take them
  `k`         sessions to read (default 6); `matching` reports what was skipped
  `strict`    refuse below 2 surviving evidence lines; `refused: true`, exit 2
  `maxUsd`    one ceiling across readers and synthesizer (default 0.10)
  `llm` / `readerLlm`   caller-owned backends. Their spend is measured as a
              **delta** and folded into `result.spend`; the caller closes them.
  `budget`    a shared `Budget`, for a caller running many questions under one cap
  `onProgress`  live cost and time; `spend.estimatedInputCalls > 0` is what
              `est.` means and the CLI inherits the label rather than guessing
  `onDrop`    every drop the filter made, with its reason. This is the audit
              trail for the product's central claim; `potsherd ask … --debug`
              prints it to stderr.
  `refusal`   on the result, not the options: why a refusal happened —
              `'strict'`, `'budget'`, `'no-answer'`, `'no-match'`. Not
              inferable from the rest of `AskResult`, which is why it is
              carried. See the note in section 5.
  `openThreads: false`  skip T4.2 entirely (it is skipped anyway when it throws)

6. two numbers the orchestrator has to decide about
================================================================================

Both are measured, both are in `phases/phase-4/evidence-T4.1/real-runs.txt`
with the runs behind them, and neither is changed here because both are set by
the plan.

**`03` §12: "ask p50 < 20 s and < $0.05 per question at k=6" is MISSED on the
subscription path.** Five real runs: 57 s, 92 s, 93 s, 100 s, 183 s. The
readers alone cost $0.061–$0.123 est. The cause is the one `03` §12 already
records for `card`: a real haiku-class call through the agent SDK is 60–160 s,
and six in parallel realise ~4.9x. The target predates any agent-SDK
measurement. **Reported as a miss rather than met by narrowing k.**

**`--max-usd`'s default of 0.10 aborts a normal k=6 run before the
synthesizer.** That is the phase-4 ruling working exactly as written — an abort
that still printed an ungrounded answer would be worse — and it fired on a real
run at $0.123 est. after six readers. `ASK_MAX_USD` is left at 0.10 because
the phase plan sets it there. The measurement says ~0.30 for k=6 on the api
path; and on the subscription path, which `04` Q4 chose, the figure being
compared against is an api-equivalent rather than money spent, exactly as `03`
§12 already says of `card`'s $2.

There is also **a race in `llm.ts` this exposed and did not fix.** `Budget.admit`
runs before a call and `Budget.record` after it, so at concurrency 6 all six
readers clear `admit` against a spend of $0 before any of them records
anything. The ceiling is enforced between batches, not within one. `ask`
catches the overshoot after the fan-out and aborts before the synthesizer, so
no run here spent past the ceiling by more than the readers' own cost — but the
race is in `llm.ts`, is not T4.1's file, and affects `card --all` the same way.
