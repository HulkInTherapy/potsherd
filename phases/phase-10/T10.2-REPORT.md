  Isolating the config dir trades a stray folder for the entire rung.

  not un-create the `projects` entry named after it). **Measured: 3 real calls → 1 directory,
  0 transcripts.** The two I created earlier are removed.

## (g) the open question you handed me: should `ask`'s shortlist run at a floor?

T10.1 left `recall()`'s floor off for `ask` and `graft`. **I think that is right for `ask`,
and for a reason the seam sharpens.**

`find` returns rows to a *human*, who acts on the ranking. `ask` returns rows to a *reader*,
whose entire job is to answer "does this session address the question — yes or no", and whose
`found: false` is cheap, expected and already handled. A floor upstream would discard the
sessions the reader is there to reject, and it would do so using a score the audit showed
carries almost no information (1.67× between a true hit and gibberish). Applying an
uncalibrated floor before a calibrated judge is strictly worse than letting the judge judge.

The one thing I would change is downstream, not upstream: when **every** reader comes back
`found: false`, `ask` should say *"your archive does not contain this"* rather than
*"the readers found nothing that answers the question"*. The first is the honest empty the
audit's §4 item 1 asks for; the second reads as a failure of the tool. That is a one-line
render change in `render/ask.ts` (reserved), so I have not made it.

Costs on the seam path are zero either way, which removes the usual argument for a floor —
there is no per-session model spend to protect.
