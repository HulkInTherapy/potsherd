# T10.13 — the per-case table

Every case the measurement judged, so that somebody can disagree with a verdict without re-running
anything. The judging rule was written and committed **before** the first candidate existed;
it is `T10.13-REPORT.md` §0.

## how to read this, and what has been taken out

- **Redaction.** No session id, project name, home path or transcript prose appears here. Projects
  are `A1`…`A14` (the map from label to directory exists only in the kept evidence directory).
  Candidates are `C001`…`C109` in the rule pass's own score order.
- **The brief asked for ids as their first eight characters. They are not here, and the reason is
  the guard.** `scripts/check-privacy.py` classes a bare eight-hex token as corpus identity under
  two separate rules, and the repository-wide inventory ceiling has zero headroom, so 109 truncated
  ids would have failed the guard on the commit that added them. Stable case labels do the same job
  — every row is re-findable in the evidence directory by its `C` number — without publishing an
  index back into somebody's transcripts. This is a deliberate departure from the brief, taken
  because the guard is binding and the brief's purpose (an id that cannot identify) is better served
  by a label that is not an id at all.
- **`what was suggested`** is my own restatement, written at the level of the technique or the rule
  and with every product, person, repository and file name removed. Where the original decision was
  about private life rather than engineering, the restatement is deliberately flatter still.
- **`cos`** is the best mention cosine the rule pass found in project B — the statistic
  `MENTION_COSINE = 0.35` is compared against. Every value in this table is below the bar, which is
  why every one of these candidates was raised.
- **`anch/files`** is the number of anchor tokens the decision shares with B, and the number of
  exact shared file paths. Two anchor tokens is the floor (`MIN_ANCHOR_TOKENS`).

## the cosine's positive side, which had never had one

*the positive side is n = 0*: the corpus held no case of project B genuinely restating A's decision,
so nothing showed that `MENTION_COSINE` catches one. **This measurement has nine.**

**The bar caught none of them.** All nine sit between 0.0910 and 0.2309, and the bar is 0.35.
Separately, the set of pairs the bar *suppressed* on this corpus is **empty** — 192 pairs reached
rule 6 and not one scored at or above 0.35 — so the bar's measured behaviour over 46 cards is: it
withdrew nothing, and it missed nine.

### the negative distribution, re-measured

| | n | median | p90 | p95 | p99 | max |
|---|---|---|---|---|---|---|
| phase 4 (45 cards) | 194 | 0.089 | 0.178 | 0.202 | 0.298 | 0.3223 |
| **T10.13 (46 cards)** | **192** | **0.1010** | **0.1581** | **0.1771** | **0.2774** | **0.3145** |

The two runs agree closely, which is the useful part: the shape of the negative side is stable.
What is new is the positive side laid over it — **the largest true positive (0.2309) is below the
negative p99 (0.2774) and well below the negative maximum (0.3145)**. There is no cut on this
statistic that admits the best true positive without also withdrawing more than a hundredth of the
non-matches, and a cut low enough to catch the median true positive (0.1217) would suppress most of
the corpus. This is the same conclusion phase 4 reached from paraphrase pairs, now reached from
measured ones.

**No threshold was moved.** The data says the statistic cannot do this job at any value, which is an
argument for changing the mechanism, not the number, and that is a design decision this task was
told not to take.
