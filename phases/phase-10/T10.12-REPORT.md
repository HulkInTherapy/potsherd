## 1. The premise was false, and it took thirty-three seconds to prove

Phases 5 through 9 all say some version of *"X is not installed here and cannot
be"*, and label the transport, four adapters and a plugin
`unverified — documentation only` on that basis. **Nobody had run `npm view`.**

| package | version | installs? |
|---|---|---|
| `@openai/codex` | 0.149.0 | yes (39 s, pre-verified by the orchestrator) |
| `@google/gemini-cli` | 0.56.0 | yes |
| `opencode-ai` | 1.18.21 | yes |
| `@github/copilot` | 1.0.80 | yes |

```
$ npm install @google/gemini-cli@0.56.0 opencode-ai@1.18.21 @github/copilot@1.0.80 --no-audit --no-fund
added 35 packages in 33s
```

**Four for four.** Rule 8 says *verify a flag exists before documenting it*. Its
mirror — *verify a tool is really unavailable before labelling it so* — had never
been applied here even once, and applying it cost thirty-three seconds and
overturned five phases of documentation.

The result is worse than "the labels were too cautious". **Three of the four
adapters were reading the wrong thing, and nobody could have known, because the
premise that stopped anyone looking was itself never checked.**

## 3. The trap I tested for the codex plugin, and why it is that one

The Claude Code trap is `~/.claude/package.json` = `{"type":"commonjs"}` poisoning
an ESM bundle. **I did not assume codex has the same one. It does not**, and the
test says so out loud:

```
$ d=$CODEX_HOME/plugins/cache/potsherd-local/potsherd/1.1.0
$ while [ "$d" != "/" ]; do [ -f "$d/package.json" ] && echo "FOUND $d"; d=$(dirname $d); done
(nothing)
```

codex writes **no** `package.json` into `$CODEX_HOME` — and `plugins/codex/`
ships no `dist/` to be mis-typed in the first place. Testing that trap would have
been theatre.

**The trap codex actually has is the missing bundle**, described above, and that
is what `tests/plugin-install.test.ts` now reproduces: the marketplace's install
path (`$CODEX_HOME/plugins/cache/<mkt>/<plugin>/<version>/`), copied alone, with
`PATH=/usr/bin:/bin` — the one thing the author's machine has that a fresh
install does not. It asserts `exit 127`, all three places named, and empty
stdout: phase 0's *"a hook that looks installed and silently does nothing is
worse than no hook"*, enforced.

**And the ESM trap does reach the codex plugin — one hop over.** Step 1b of
`bin/potsherd` runs `../claude-code/dist/potsherd.js`, which is ESM *only*
because `plugins/claude-code/package.json` says so. So the whole codex block runs
under a `{"type":"commonjs"}` parent anyway, and asserts both directions: with
the neighbour's `package.json` it runs and prints a version; with it removed the
codex plugin fails with `Cannot use import statement` — the v1.1.0 crash,
reproduced through the codex shim.

One guard for the future: the suite now fails if `plugins/codex/dist/` ever
appears, naming the decision that has to be made with it.

## 5. What the copilot `session-state` investigation found

`08 §3` item 7 flagged it: *the Copilot CLI has run here and has still written no
`session-state/`*. **The adapter's path was never the problem.**

```
$ cat ~/.copilot/logs/process-*.log
… [INFO] Starting CLI in server mode (stdio)
… [INFO] Starting CLI in stdio mode (Rust JSON-RPC engine)
… [INFO] Destroying 0 active sessions
```

Every run on this machine was the IDE's stdio JSON-RPC engine, and every one
destroyed **zero** sessions. Copilot writes `session-state/` per *CLI* session,
and there had never been one. One `copilot -p "say hello"` under a relocated HOME
created the directory on the first attempt — *before* it even failed at auth.

What that directory contains is the finding, and it is not what the adapter
reads: `workspace.yaml`, `checkpoints/index.md`,
`rewind-file-snapshots/tracking.json`, and empty `files/` and `research/` — none
of the six names in `STATE_FILES`, and no JSON document of turns anywhere. **The
transcript is one level up, in `~/.copilot/session-store.db`**, a sqlite database
whose `turns(session_id, turn_index, user_message, assistant_response, timestamp)`
is almost exactly potsherd's `Exchange`, with an FTS index beside it. potsherd
never opens it, and reports `copilot 0 · no transcripts in ~/.copilot/session-state`
over a real, non-empty install. Full evidence and the recommended adapter in
`T10.12-LABELS.md §5`.

## 6. Isolation — the lever per tool, and how it was checked

| tool | lever | result |
|---|---|---|
| codex | `CODEX_HOME=$CX` (and `HOME` for the plugin work) | sessions, config, plugins, all six sqlite stores landed in the scratch home |
| copilot | `HOME=$CP`, `-u XDG_CONFIG_HOME` | `~/.copilot` untouched |
| gemini | `HOME=$GH`, `-u XDG_CONFIG_HOME`, `-u GEMINI_API_KEY` | `~/.gemini` untouched |
| opencode | `HOME=$OC`, `-u XDG_CONFIG_HOME`, `-u XDG_DATA_HOME` | `~/.local/share/opencode` never created on the real HOME |
| potsherd | `--potsherd-dir "$(mktemp -d)"` on **every** run, plus a relocated `HOME` | `~/.potsherd` untouched |

`ls` before and after:

```
$ ls -laR ~/.copilot   → config.json · ide/ · logs/          (identical before and after)
$ ls ~/.gemini         → antigravity · antigravity-browser-profile · GEMINI.md   (no tmp/)
$ find ~/.codex -name 'rollout-*.jsonl' | wc -l   → 1 before, 1 after
$ diff codex-home-BEFORE.txt codex-home-AFTER.txt | grep -c sessions   → 0
```

**One honest exception, disclosed.** `diff` of `~/.codex` is not empty: 34 lines,
**all of them `~/.codex/tmp/arg0/`**. codex 0.149.0 recreates its execve-wrapper
shim directory (a `.lock` and three symlinks to the codex binary) under the
*real* `~/.codex` for any invocation that does not set `CODEX_HOME` — and
`codex --version` and `codex exec --help`, run before isolation was in place, did
exactly that. It is regenerated per run and contains no session, config, auth or
transcript data; `sessions/` does not appear in the diff at all. **Anything in
this project that shells out to codex should set `CODEX_HOME` even for `--help`.**

The developer's `~/.codex/auth.json` was **not read and not used**. A real codex
model call was available for the taking by copying it into the scratch
`CODEX_HOME`; that would have spent the developer's account, so it was not done,
and the 401 is reported as the blocker instead.

## 7. What I changed, and the large thing I deliberately did not

**Changed:**

- `tests/plugin-install.test.ts` — the codex plugin, under the trap codex
  actually has (§3). 5 new cases; the file went from **zero** occurrences of
  `codex` to a full second block.
- `tests/adapters/{codex,copilot,gemini,opencode}.test.ts` — one measured-shape
  block each, 15 cases, every fixture hand-written from scratch to the observed
  SHAPE. No real session id, project name, home path or prose. Invented ids carry
  2 distinct hex digits in their first eight, under the entropy guard's 3.
- `tests/fixtures/opencode/make-opencode-db.mjs` — `buildOpencodeReal()`, the
  real 1.18.21 schema as a reviewable builder rather than a committed binary.
- `phases/phase-10/T10.12-LABELS.md`, this file.

**NOT changed: any adapter source, and `packages/core/src/llm.ts`.**

- **`llm.ts` was already done.** `CodexTransport` at `HEAD` already carries
  `--ephemeral`, `--ignore-user-config` and `-o/--output-last-message`, with the
  narrowed label ("the argv is verified; the round trip is not, and those are
  different claims"). I re-read `codex exec --help` at 0.149.0 and **confirm every
  flag it names is real**, including the three additions and `-` for stdin. There
  was nothing left to take.
- **the four adapters are untouched on purpose.** *"Do not change an adapter to
  match one real session unless that session proves the adapter is wrong. One
  transcript is a sample of one."* Three sessions do prove three adapters wrong —
  but every fix is a **new read path**, not a correction: a sqlite title source
  for codex, a `part` join for opencode, a whole second sqlite adapter for
  copilot, a `projects.json` source for gemini. Writing four new parsers against
  one session each is precisely the failure this task exists to prevent, and two
  of the four files are outside the delivery list anyway. So: exact recommended
  edits in `T10.12-LABELS.md`, applied by whoever has a second session to check
  them against.

  The tests are the tripwire. Each `FINDING` case asserts what the adapter does
  **today**, names the section of `T10.12-LABELS.md` that explains it, and fails
  the moment someone fixes it.

## 8. What I could not do

1. **A codex model round trip.** `401 Unauthorized`. No credentials that are ours.
2. **A gemini session of any kind.** `Please set an Auth method … GEMINI_API_KEY,
   GOOGLE_GENAI_USE_VERTEXAI, GOOGLE_GENAI_USE_GCA`. None available; the OAuth
   paths need an interactive browser and the developer's quota. **`gemini`'s
   `unverified` label is kept for exactly this reason, and keeping it is the
   correct outcome.**
3. **A copilot model round trip.** `No authentication information found` — needs
   `COPILOT_GITHUB_TOKEN`/`GH_TOKEN`/`GITHUB_TOKEN` or `gh auth login`. The
   session directory and its sqlite were created without one, which was enough to
   settle the question that mattered.
4. **Confirming the codex plugin's MCP server registers.** `codex doctor` says
   `MCP servers 0`; whether that is a manifest omission or a doctor that only
   counts config-declared servers is unresolved (§2).
5. **`SessionEnd` firing.** It needs a session that completes, which needs (1).
