  "the project started on 3 June"

**v1.1.0 behaviour — measured, not asserted.** There was exactly one citation
check in the product and it is `CITATION_RE` (`/([0-9a-f]{6,40})@(\d+)/gi`), the
`[id8@seq]` pattern `graft` resolves and `filterAnswer` runs the same discipline
on. Run over the block above it returns **zero matches**. That is not a bug in
`CITATION_RE` — it is the level it runs at. A `SOURCES` row holds no `id8@seq`,
so it is ordinary prose, so *cited or dropped* leaves it alone. All four rows
survive character for character, including `HANDOFF.md §3` and the fabricated
date. Two tests pin this so nobody can claim the old surface was covered.

**Now.** `verifySources(db, block)`:

| field | reason | outcome |
|---|---|---|
| `11111111` | — | **kept**, resolves to the fixture session |
| `§3` (from `HANDOFF.md §3`) | `not-an-id` | refused |
| `—` | `no-id` | refused |
| `deadbeef` | `unresolved` | refused |

Three refused, one kept, and each refused row takes its indented quote with it —
`HANDOFF.md`, `the payment gate was cut from scope` and `the project started on
3 June` are all absent from the returned text. The note names the fix:
*"A source line is a session id that resolves against the index… Copy the
citation potsherd_recall or potsherd_read gave you."*

It runs at runtime, not only in tests: **`potsherd_graft` passes its brief through
`verifySources` on every call** and reports `refusedSources[]`. It is also in
`--selftest`, against a live index (`verifySources refused 2 fabricated source
lines, kept 1 real one`).

**One false positive I caught and fixed, because it matters more than the fix it
was part of.** My first detector took any line with three `·`-separated fields.
The very first thing it refused was `graft`'s own true footer

a *worse* failure than the fabrication. The grammar is now: `·`-separated, ≥3
fields, and one field is a count of exchanges or the ghost marker. Both shapes
are pinned by tests.

capability rather than relocating it — `find`→`recall`, `ls`→`recall`, and `ask`→

not exist in this tree, so I could not build the fourth tool that should occupy the slot.

`recall · read · graft · note` — three ways to read and one way to leave something behind.
