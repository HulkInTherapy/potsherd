ONE SEMANTIC THAT MATTERS AND IS EASY TO GET BACKWARDS:

  prompt — and on `remembering-sessions` it would buy nothing, which is why

1a. `plugins/claude-code/bin/potsherd` — THE SHIM. NOBODY OWNS THIS.
--------------------------------------------------------------------------------
The WAVE table assigns `.claude-plugin/**`, `hooks/**`, `.mcp.json` and
`marketplace.json` to T5.3 and `skills/**` + `agents/**` to me. `bin/**` is in
neither column, and `/potsherd` does not run without it. Flagging rather than
creating it, because it is outside my four delivered paths.

What it has to be:

    plugins/claude-code/bin/potsherd          # mode 0755
    ------------------------------------------------------------------
    #!/bin/sh
    # Reach this plugin's own potsherd. Never the one on PATH.
    exec node "$(CDPATH= cd -- "$(dirname -- "$0")/.." && pwd)/dist/potsherd.js" "$@"

And a REAL CONSTRAINT on how `dist/` gets there, measured on the built bundle:

    packages/cli/dist/potsherd.js is a single esbuild file, and it still
    resolves `better-sqlite3` and `sqlite-vec` at runtime through
    `createRequire`. Copying the one .js file is not enough — it needs a
    `node_modules` beside it with better-sqlite3 built for the host platform.
    (`@anthropic-ai/claude-agent-sdk`, `@anthropic-ai/sdk` and
    `@huggingface/transformers` are dynamic `import()` and are optional.)

    So the two workable shapes are:
      (i)  the plugin vendors `dist/` + a real `node_modules` (per-platform), or
      (ii) `bin/potsherd` execs the installed npm package, and the plugin
           declares `potsherd` as a prerequisite.
    (ii) is smaller and (i) is the one that honours "`potsherd` on PATH may be
    stale or absent". T5.6's packaging decision, not mine.

    Interim, for the manual tests in section 3: symlink the shim at the repo's
    own built binary. Section 3 step 1 does exactly this.

2. THE ONE THING THAT COULD NOT BE BUILT — `readerFn` FROM MARKDOWN
================================================================================

ASKED FOR PLAINLY, SO ANSWERED PLAINLY:

  **A SKILL.md cannot supply `readerFn`. Not partially, not with a workaround.**

`AskOptions.readerFn` is a TypeScript function passed to `ask(db, question, o)`
by a TypeScript caller. A SKILL.md is markdown: its only executable surfaces are
(a) Bash commands, and (b) Claude Code's own tools. Neither can hand a closure
to a library function inside a `node` process it did not write. The T4.4
interface is correct and complete — it is simply an interface for a *program*,
and phase 5's claude-code surface is not a program. Nothing in `packages/cli`
exposes it either: `potsherd ask` has fourteen flags and not one of them takes
reader input or emits reader input.

WHAT THE SKILL DOES INSTEAD, AND WHAT IT COSTS

`skills/potsherd/SKILL.md` reproduces the *shape* of the fan-out in markdown:

    BIN find --json --limit 6 --vectors on   →  the shortlist  (binary, no model)
    BIN show --json --from --to  ×6          →  the excerpts   (binary, no model)
    six native Agent calls in one message    →  the readers    (parallel, free)
    the main context                         →  the synthesizer

with `READER_SYSTEM` quoted verbatim out of `ask.ts` so the readers behave
identically, and with `--limit 6 --vectors on` pinned because `recall` derives
candidate depth from `limit` (a wider limit re-orders the top six — that is
`ask.ts`'s own measured comment) and `ask` defaults vectors on where `find`
defaults to auto.

**What is lost is `filterAnswer`.** That is the code-level citation filter that
runs after the synthesizer replies and deletes any quote that does not resolve
to real bytes at the `(sessionId, seq)` it names, plus any sentence left with no
surviving evidence. It is the product's central claim — `00`'s "cited or
dropped", `05`'s honesty contract — and it is enforced *by code, not by trust*,
which is exactly the property markdown cannot reproduce. The skill therefore
checks quotes by reading, prints a last line saying so, and routes to
`potsherd ask` for the code-checked answer. It does not claim the guarantee.

THE FIX — TWO FLAGS, BOTH PURE CLI-LAYER, NO CORE CHANGE AT ALL

Not built here (`packages/**` is RESERVED and the brief says report, do not
add). Specified precisely because it is small, and because it turns the fast
path from "weaker" into "identical, twenty times quicker".

  potsherd ask "<q>" [filters] --readers-out <path>
      Runs the shortlist and the excerpt build, writes JSON to <path>, exits 0.
      **Makes no model call.**  <path> holds:
          { "question": "...", "targets": [ AskReaderInput, ... ] }
      i.e. the exact `input` object T4.4 documents, one per shortlisted session,
      already carrying `excerpts`, `seqs`, `isGhost`, `isSidechain`.

  potsherd ask "<q>" [filters] --readers-in <path>
      Skips shortlist and readers. Reads <path>:
          [ { "sessionId": "...", ...AskReaderOutput }, ... ]
      and runs the synthesizer, `filterAnswer`, open threads and the normal
      renderer. **One model call.**

Both are implementable *entirely through the existing public `AskOptions`*,
inside `packages/cli/src/commands/ask.ts`, with no edit to `ask.ts`:

  --readers-out : pass a `readerFn` that records `input` into an array and
                  returns `{found:false, quotes:[], answer_fragment:''}`.
                  Every reader reports nothing, so `ask` hits its own
                  `answered.length === 0` early return and never reaches the
                  synthesizer. Write the array. Zero model calls, by
                  construction rather than by a flag check.
  --readers-in  : pass a `readerFn` that looks the recorded output up by
                  `input.sessionId` and returns it, `{found:false,…}` when
                  absent. `ask` then does the whole of the rest of its job
                  unchanged — including `filterAnswer`.

The two together are the first real *use* of the T4.4 interface, and they are
what a SKILL.md can drive: two Bash calls with an Agent fan-out between them.
When they land, replace steps 1–3 and 5 of the `ask` route in
`skills/potsherd/SKILL.md` with them and delete the "checked by reading"
caveat — the guarantee becomes the shipped one.

Estimated size: ~40 lines in one CLI file, plus tests. Suggest T5.7 or phase 7.
