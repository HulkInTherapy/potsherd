2. THE .mcp.json STANZA A CLIENT NEEDS
================================================================================

The server is a plain stdio server: one command, no arguments required.

2a. Claude Code plugin (`plugins/claude-code/.mcp.json`, T5.3's file):

    {
      "mcpServers": {
        "potsherd": {
          "command": "node",
          "args": ["${CLAUDE_PLUGIN_ROOT}/mcp/index.js"],
          "env": {
            "POTSHERD_GRAFT_CWD": "${CLAUDE_PROJECT_DIR}"
          }
        }
      }
    }

    `${CLAUDE_PLUGIN_ROOT}/mcp/index.js` assumes the plugin bundles
    `packages/mcp/dist/index.js` at `mcp/index.js`, in the same way it bundles
    the CLI at `bin/potsherd`. If T5.3 lays the plugin out differently, only
    that one path changes. **`POTSHERD_GRAFT_CWD` is worth setting** — see §3.

2b. Cursor (`.cursor/mcp.json`), and the same JSON for gemini cli, opencode,
    copilot and pi, which all take the stdio shape:

    {
      "mcpServers": {
        "potsherd": {
          "command": "node",
          "args": ["/absolute/path/to/potsherd/packages/mcp/dist/index.js"]
        }
      }
    }

    Cursor launches a stdio server in the workspace folder, so `graft`'s brief
    lands in the project without `POTSHERD_GRAFT_CWD` being set. A client that
    launches it somewhere else needs the variable; the tool says so in its own
    reply when it happens.

2c. Every environment variable this server reads, in full:

    POTSHERD_DIR                  the index to read. Same as --potsherd-dir.
    POTSHERD_GRAFT_CWD            where potsherd_graft writes its brief.
    POTSHERD_MCP_ASK_TIMEOUT_MS   how long potsherd_ask may run. Default 240000.

    There is no other configuration and no config file.

2d. Verifying an install without a client:

        node packages/mcp/dist/index.js --selftest    # exits 0
        node packages/mcp/dist/index.js --help

3. THE DECISION ABOUT `graft`'s CWD — READ THIS BEFORE T5.3 WRITES .mcp.json
================================================================================

`graft` writes `./.potsherd/graft-<id8>.md` into the process's working
directory. For the CLI that is where the user typed the command, which is by
construction the project they meant. **For a stdio server it is wherever the
client happened to launch it**, which is `/` in some desktop clients and the
client's own bundle directory in others.

The rule implemented (`resolveGraftCwd` in `packages/mcp/src/context.ts`):

  1. `POTSHERD_GRAFT_CWD` wins absolutely.
  2. otherwise the process's cwd, if it exists, is a writable directory, and is
     **not** the filesystem root, `$HOME`, or the system temp directory.
  3. otherwise nothing is written: `graft` runs with `write: false`, the reply
     carries `path: null`, `wrote: false` and a `writeNote` naming
     `POTSHERD_GRAFT_CWD`, and the brief — always the actual deliverable — is
     returned inline.

Consequences the integrator should know:

  - **No new write path exists.** `./.potsherd/graft-<id8>.md` is the same path
    `doctor --privacy` already discloses, and no `.potsherd/` directory is ever
    created in `$HOME` or `/`. The published privacy receipt does not drift and
    the CI guard on it stays green (verified: `pnpm test` 1,067 green, which
    includes the three `doctor --privacy` tests in `tests/cli.test.ts`).
  - **A `.mcp.json` should still set `POTSHERD_GRAFT_CWD`** where the client
    exposes a project variable, because rule 2 is a guess and rule 1 is a fact.

4. WHAT IS DELIBERATELY NOT HERE: A `potsherd mcp` VERB
================================================================================

`03` §9 lists `mcp` among the CLI's verbs. It is **not** added, for two
reasons, and both are the integrator's to overrule rather than mine:

  1. It needs `packages/cli/src/index.ts`, which is RESERVED.
  2. It would put a command in `packages/cli/src/commands/` that reaches a
     model — `potsherd_ask` and `potsherd_graft` both call `Llm.open` — while
     `MODEL_CALL_VERBS` is `['card','ask','graft']`.

  **And the guard would not catch it.** `tests/llm.test.ts` follows a command's
  imports *from `@potsherd/core`* and checks whether the module behind each one
  calls `Llm.open`. A `commands/mcp.ts` importing from `@potsherd/mcp` matches
  no `@potsherd/core` import, so the guard would pass a verb that spends money.
  This is a real blind spot in a guard whose whole job is to have none, and it
  is reported rather than patched because `llm.ts` and the test are not mine.

  If the verb is wanted, the smallest correct change is:

    packages/cli/src/index.ts:
      import { runMcp } from './commands/mcp.js';
      program.command('mcp').description('speak MCP on stdin/stdout')
        .action(async () => { await runMcp(globals(program, mcp, {})); });

    packages/core/src/llm.ts:
      export const MODEL_CALL_VERBS: readonly string[] =
        ['card', 'ask', 'graft', 'mcp'];

    and `tests/llm.test.ts`'s scanner extended to follow `@potsherd/mcp`
    imports the same way it follows `@potsherd/core` ones.

  Until then the server is reached as `node packages/mcp/dist/index.js` or as
  the `potsherd-mcp` bin, which is what every `.mcp.json` in §2 names.

5. ONE PLACE THE PINNED CONTRACT AND MCP'S OWN VOCABULARY DISAGREE
================================================================================

Reported, not changed, per the brief.

`WAVE.md` says *every tool is read-only except `potsherd_tag`*, and in the next
clause *nothing writes outside `~/.potsherd` except `potsherd_graft`'s brief,
which lands in the cwd*. So the contract knows `graft` creates a file and calls
it read-only anyway — which fixes what "read-only" means here: **it modifies no
state that anything else reads.** Not the index, not the archive, not a
transcript, not a tag.

MCP's `readOnlyHint` is defined more broadly, as "does not modify its
environment", and by that reading a new `./.potsherd/graft-<id8>.md` is a
modification. `potsherd_graft` therefore ships with `readOnlyHint: true`,
following the pinned wording, because four workers are compiling against it.

Nothing is hidden by that choice: the tool's description says it writes the
brief and names the file, and every reply carries `path`, `wrote` and
`writeNote`. If the orchestrator would rather the annotation followed MCP's
definition, the change is one line in
`packages/mcp/src/tools/graft.ts` (`readOnlyHint: ctx.graftCwd === null`) plus
the matching line in `packages/mcp/src/server.ts`'s `WRITE_TOOLS` and one test.

No other field, name or shape in the pinned contract needed changing. All six
tools were buildable exactly as written.
