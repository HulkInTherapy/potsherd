ANSWER
  Transaction pooling mode drops session state, so server-side prepared
  statements don't survive across a transaction boundary. [1] The decision was
  to have the client stop preparing statements by setting
  statement_cache_size=0. [2] This was verified: the test failed with the old
  client config, showing a "prepared statement already exists" error, and passed
  once the cache was disabled. [3]
