# Slopie terminal audit

`slopie audit` opens the retrospective. `--legacy` opens the retention audit; `--sweep` and `--verify` keep their prior routes. Slopie was formerly named Potsherd; `potsherd audit` remains a compatibility command. This checkout is the 1.6.1 branding candidate, with npm publication pending. Earlier installed receipts remain bound to their Potsherd 1.6.0 builds; a source test is not new installed or live-provider proof. See the [Slopie repository](https://github.com/HulkInTherapy/slopie).

The first wall shows all-time recorded API-equivalent value at a named Models.dev snapshot, token/pricing coverage, a favourite model combining equal token and conversation measures, real project names, recent work and short source quotes. Known priced portions are distinct from unknown usage and pricing. A separately labelled first-party reference can value approved model IDs with an unknown actual provider; it does not identify their serving endpoint. Known normalized token subtotals remain distinct from unknown full totals. Main chats exclude children; model usage chats include attributable agent conversations. The value is a revaluation at current catalog rates, not an invoice or subscription bill. Native per-response models/providers and token buckets preserve cache/reasoning inclusion and cumulative/duplicate semantics. Unknown endpoint, custom model and unmatched revisions remain unknown. pi/OpenCode user projections do not establish human authorship.

Left/right or Tab switches Models, Projects, Work, Hall of Fame, Language and Timeline. Up/down selects, Enter opens details or exact source evidence, Esc returns, S freezes the current visible view, q exits. W exposes the available periods and their remaining-analysis estimates before an expanded analysis. These estimates include questions/retry allowance after local inventory and are not total cold-audit times. The command's total token reservation includes all calls and retries across period changes. Real project names and selected source lines remain visible in a frozen view; JSON and explicit safe SVG exports use the separate public aggregate serializer. No automatic posting occurs.

An opening notice names OpenCode Zen and TypeSafe/Jev as recipients of selected redacted conversation text. There is no additional startup Enter prompt or consumer key requirement. The official OpenCode loader keeps zero-input-cost models available without authentication and uses the public literal credential; this is not an embedded account secret. Earlier requests for an authored synthetic sample returned HTTP 200 with zero cost and validated typed answers. Current capacity is constrained: all four authorized private requests returned quota errors and no accepted answers. Private semantic accuracy is unavailable, not a failed or passed four-case accuracy score. An owned-key probe also hit a local daily limit before authentication; it did not establish key validity or restore capacity. Client-side concurrency, request/deadline/token reservations, cancellation and strict zero-cost responses bound the direct route. No paid model, billing enrollment, automatic reload or key embedded in npm is a fallback. Capacity loss leaves local facts and completed cached work intact; another invocation may resume after legitimate capacity becomes available. Private developer pilots require exact payload review and authorization independently of this consumer design.

The local pipeline inventories native sources, sizes complete contextual segments, selects All/45/30/7/3 days within the same allowance, or a visibly partial selection of the newest whole episodes when calendar windows exceed it, and asks typed Choice/Score/Noul questions. Complete conversations fit one segment; long histories use complete turns with preceding context and explicit gaps. Standalone oversized turns are skipped with coverage, never silently truncated to a successful prefix. Work attempted, assistant-reported success and success supported by recorded results are distinct. User tone/quotes require direct-user evidence. Literal profanity uses a versioned English lexicon and conservative direct/quoted/code/unknown buckets; it does not diagnose personality or claim multilingual coverage.

Source stores remain read-only. Existing frozen SQLite, live-WAL holds, per-record project/ignore, forget, lineage, redaction and currentness fences apply before transfer, cache use and source reads. Changed source or policy clears launch findings. Derived usage, typed answers and verified date intervals live separately under `audit-derived`, with0700directory/0600files and atomic writes; full conversation bodies and selected quotes are not stored in that cache. Cache identities bind content, currentness, source/privacy/forget, question/model/segmentation versions. Date skips require actual verified event intervals and unchanged identity; mtime is never an event-date substitute. Public catalog refresh is bounded and saves a validated snapshot for future reports; it does not silently reprice an existing report or rerun Jev.

The retrospective remains experimental. Prior installed Node 22 receipts cover factual arithmetic, exact source boundaries, cached typed answers and real terminal journeys; later offline replays are not new live-provider proof. The unchanged 322-file / 10.9 MB synthetic fixture took about 33 seconds cold and 22 seconds warm, so the proposed 5–10 second first-wall goal was not met on that large fixture. Independent, untuned scores were usefulness 7/10, ease 8/10 and appearance 8/10 at 80 columns (7/10 at 40). Four of seven work categories abstained, and the sample contained no successful tool-result span, leaving positive supported-success accuracy unqualified. Current private semantic accuracy remains unavailable because of quota errors.

The Slopie package and compatibility alias require their own installed branding/version/provenance checks before publication. Earlier terminal receipts cover 120×40, 80×24 and 40×20, including ASCII, no-color, reduced motion, resize, cancel, back, freeze and terminal restoration, with each result bound to its tested build. Existing storage, cache, settings, plugin and tool identities retain their compatibility names.
