# Slopie terminal audit

`slopie audit` opens a fullscreen wallboard. The `potsherd` executable remains compatible. `--legacy` opens the local retention audit; `--sweep` and `--verify` keep their existing routes.

The board shows current API-equivalent value, known tokens, models and pricing, three projects with source-backed requested-work tags, repeated short user-role lines and observed model-directed reactions. Wide terminals show the meaningful cards together; smaller terminals use left/right mixed-content pages. There are no section tabs or scrolling controls. `?` opens help, `s` freezes presentation while paging/help/quit remain usable, `d` reads a captured source, Esc returns and `q` exits. Paste does not trigger commands. ASCII, no-color and reduced-motion paths retain the data. Plain output prints the complete report without a viewport cap; JSON and safe SVG use the public aggregate representation.

## Native usage and pricing

Claude Code supports both conventional config roots and comma-separated `CLAUDE_CONFIG_DIR`; Codex includes main and archived sessions and `CODEX_HOME`; pi respects its agent-root/session settings; OpenCode reads supported SQLite layouts and grouped legacy session/message/part JSON. Explicit source flags retain their scope. Unsupported layouts and bounded omissions remain visible rather than appearing as empty history.

Native files are inventoried before expensive retained-history work. Full response usage streams separately from bounded conversational context. The native inventory is capped at 50,000 selected files and 4 GiB of original data. Oversized records, incomplete tails and format gaps are disclosed. Retained revisions provide fallback for missing native identities; they do not replace or duplicate native usage. Ignored projects, actual forget tombstones, forgotten sources, opt-out markers and per-record project boundaries apply throughout.

Message/request identity, whole-record streaming completion, explicit fork/copy boundaries and cumulative counters determine deduplication. Cache/reasoning inclusion is host-specific. Serving models come from recorded response or active turn metadata; a workflow name is not an actual model. Conflicting model identities remain unknown while their most complete whole usage vector can remain observable. Synthetic usage is excluded. Native user-role activity is separate from strict authorship attestation; known orchestration channels do not become personal phrasing or feedback, while real child inference remains usage.

Value is a revaluation at a dated Models.dev catalog, not a historical invoice or subscription bill. Provider-specific rates, context tiers and coverage are retained. An exact catalog-known Claude identity can use a named current Anthropic first-party reference when its actual serving provider is unrecorded. Explicit five-minute and one-hour creation buckets use the documented corresponding rates; unknown or contradictory duration splits are not guessed. Native reported API-cost fields are a separate recorded basis. Local or unmatched models remain unpriced unless an unambiguous explicit reference is configured. Known portions remain distinct from unavailable totals.

Source-backed work tags describe literal requested tasks, not completion or active hours. Repeated profane lines are grouped by normalized case/punctuation while the displayed variant remains source-exact; bounded examples are separate from full counts. Directed negative and praise observations require explicit feedback context linked to a recorded assistant model. Self-directed frustration, quoted/code/assistant language and ambiguous targets do not become model criticism. Counts and available denominators describe recorded reactions, not objective benchmark performance. The lexicon is English and does not claim multilingual or universal sentiment coverage.

## Responsive work and privacy authority

File parsing, SQLite work and semantic preparation run in a separate process. The renderer owns input and incremental frames; cancellation rejects pending operations, terminates blocked work within a bounded fallback and cleans only owned temporary directories. Ready results have no animation polling loop. Source appends do not revoke already captured redacted details; latest ignore/forget/privacy changes do. Captured results do not authorize a new request against changed source content.

Retained privacy metadata is read through normal enforced read-only SQLite transactions. No immutable assumption, migration, checkpoint or journal-mode change is used. SQLite may maintain SHM coordination and an empty zero-byte WAL sentinel; database and WAL history payloads are not written. Before reading policy, official WAL checksums and an independently validated duplicated WAL-index header establish the published committed boundary. Missing/inconsistent metadata, damaged committed frames, nonempty rollback journals and unsafe changes cause a typed local hold. Only unchanged certified identities can reuse verification. The cheap guard reads the database header and bounded WAL, not a multi-gigabyte database backup. This is not a whole-database integrity certification.

Actual tombstone/deletion sets, including manual changes without epoch increments, and ignore configuration are re-read at authority boundaries. Ordinary evidence/notes/lineage appends do not alone revoke a capture. New semantic dispatch and cache return retain full captured-source/currentness checks. Native SQLite capture where needed uses bounded private copies, never source checkpointing or journal deletion. Temporary data is owner-only; cancellation cleans the owned job directory.

Derived usage, typed answers and verified date intervals live separately under `audit-derived`, with owner-only permissions and atomic writes. Conversation bodies and selected quotes are not written to that cache. Bindings include content, currentness, scope, privacy/forget, question/model and segmentation versions. Date skips require verified event intervals, not mtime. A public catalog refresh does not silently reprice an already displayed report.

## Optional remote semantics and limits

Selected conversations are redacted locally. Only immediately before an actual request does the parent display the full recipient notice naming OpenCode Zen and TypeSafe/Jev; a physical render/flush acknowledgment precedes fetch. Two concurrent notices are kept distinct, cancellation suppresses late acknowledgments, and a failed disclosure cannot silently dispatch. Offline or cached work does not claim a transfer. No extra Enter, account secret, billing enrollment, reload or paid fallback is required by the public free route.

The exact free model and zero-cost response contract are enforced alongside request/deadline/token reservations. The largest fitting All/45/30/7/3-day scope is selected, or a labelled selection of newest whole episodes. Window estimates describe remaining analysis after inventory, not total cold-command time. Long histories use bounded complete turns and explicit gaps. Requested work, assistant-reported results and supported outcomes remain distinct; no unsupported Hall-of-Fame quote or success is manufactured.

Earlier public synthetic calls returned validated zero-cost answers. Private semantic validation remained unavailable after quota errors, including a later local test-IP limit before authentication; upstream recovery was not established. Those failures are neither an accuracy pass nor zero model accuracy. Local facts remain usable when the provider is unavailable. Agent-run private validation requires separate scoped authorization; a build task does not authorize new private transfers.

The retrospective remains experimental. Controlled fixtures, real installed consumer receipts and live-provider evidence have different scopes and are bound to their tested versions. Large inventories, native-format ambiguity, missing rates and active-source changes can limit coverage or latency. No universal speed, semantic accuracy or model-quality claim is made. Existing storage/settings/cache/plugin/tool identities remain compatible; managed plugin caches are not manually rewritten during a CLI upgrade.
